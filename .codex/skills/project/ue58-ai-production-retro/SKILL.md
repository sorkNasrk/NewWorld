# AI Production Retrospective

Create a retrospective when the same AI mistake happens twice, when one failure causes meaningful rework, or when a tool/process assumption proves wrong. Read [references/rule-writing.md](references/rule-writing.md) before proposing durable rules.

## Required Inputs

- Original task and expected outcome.
- Failure symptom and affected files/assets.
- Root cause based on evidence.
- Correct fix and verification.
- Whether the issue should change AGENTS.md, a project skill, or only a retrospective.

## Rule Criteria

Write a durable rule only when it changes future decisions. The rule must include trigger, bad example, correct behavior, verification, scope, and expiration/review condition.

## Output

Append a concise entry to Docs/Planning/AI_PRODUCTION_RETROSPECTIVES.md and propose at most three rule updates. Do not turn one-off preferences into global rules.
